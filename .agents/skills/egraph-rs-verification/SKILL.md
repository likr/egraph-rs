# Verification and Testing Guide for `egraph-rs`

This skill defines the tiered verification harness across Native Rust, Python (PyO3), and WebAssembly (`wasm-bindgen` / Node / Browser) in `egraph-rs`.

## 1. Tiered Verification Runner (`scripts/verify.sh`)

**Staged Verification Sequence**: Always verify Rust core changes first (`--fast --crate <name>`, then `--rust --invariants`) until the Rust API is stable; only then build and verify Python (`--python`) and WASM (`--wasm --build-wasm`) bindings, followed by `--parity` and `--docs`.

Always prefer `./scripts/verify.sh` over raw `cargo`/`maturin`/`unittest` invocations. It automatically sets:
- `RUST_FONTCONFIG_DLOPEN=1`
- Single-thread guards (`OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, `MKL_NUM_THREADS=1`, `RAYON_NUM_THREADS=1`, `NUMEXPR_NUM_THREADS=1`)
- `RUSTC_WRAPPER=sccache` (shared compilation cache across git worktrees; if deep sandbox `TMPDIR` paths trigger Unix socket `SUN_LEN` errors during `cargo clippy`, bypass cleanly with `RUSTC_WRAPPER=env` without altering repository files)
- `CARGO_BUILD_JOBS` throttled by `EGRAPH_PARALLEL_WORKERS` (`1->8`, `2->5`, `3->4`, `>=4->2`)
- Isolated worktree-local `$REPO_ROOT/.venv` (`uv`-managed Python 3.12)
- `cargo nextest run` when installed

| Tier | Command | When to Run |
|---|---|---|
| **Tier 0 (`--fast`)** | `./scripts/verify.sh --fast [--crate <name>] [--json-summary <path>]` | After every local edit in a worktree (stays debug for quick crate loops; checks `rustfmt`, `clippy -D warnings` + `clippy.toml`, `nextest` on changed/`--crate` packages, `std::thread` scan). For binding crates: `--crate egraph-python` runs `clippy` and directs to `--python`; `--crate egraph-wasm` runs `wasm32` check + `clippy` and directs to `--wasm`. |
| **Tier 1 (`--rust`)** | `./scripts/verify.sh --rust [--debug-rust] [--strict]` | Before merging a Rust crate branch (full workspace `fmt --check`, `clippy`, and release `nextest --workspace` + `egraph-cli` + 4 feature-matrix passes via `run_pkg_matrix`: `ALL_FEAT_CRATES` [12 crates `--all-features`], `NO_DEF_CRATES` [10 crates `--no-default-features`], `BASELINES_CRATES` [5 crates `--no-default-features --features baselines`], and `DELAUNAY_CRATES` [5 crates `--features delaunay`]; `--debug-rust` opts into debug tests; `--strict` includes legacy `petgraph-linalg-kernel`). |
| **Tier 1 (`--python`)** | `./scripts/verify.sh --python [--test <module>] [--dev-py]` | After Rust core is verified and `crates/python` bindings are updated (rebuilds with `maturin develop --release` by default into local `.venv`; `--dev-py` opts into debug builds and `--release` remains accepted; runs `unittest`, `mypy --strict` on `crates/python/python/egraph` and the 25 strictly typed domain test files `TYPED_PY_TEST_NAMES`, and `stubtest egraph` across all 25 package modules: `__init__.py`, `interop.py`, `_core.pyi`, `_core_types.{py,pyi}`, and 21 `_core_<domain>.{py,pyi}` pairs). |
| **Tier 1 (`--wasm`)** | `./scripts/verify.sh --wasm [--test <name>] [--build-wasm]` | After Rust core is verified and `crates/wasm` bindings are updated (`wasm32` check + `wasm-pack test --node` across default `full = ["delaunay"]`, `wasm_test_minimal` running all 26 feature-ungated domain `[[test]]` targets `WASM_MINIMAL_TARGETS` with `--no-default-features`, and `--features legacy`; `--build-wasm` runs `(cd crates/wasm && wasm-pack build --target web --no-opt --profile wasm-release -d pkg .)` requiring `wasm-pack >= 0.14` / `v0.15.1` + `assemble_pkg.mjs` delegating to `crates/wasm/scripts/assemble/*.mjs` [11 modules] + explicit `wasm-opt -Oz --enable-bulk-memory --enable-nontrapping-float-to-int` + `node crates/wasm/tests/node_esm_smoke.mjs` delegating to `crates/wasm/tests/esm_smoke/*.mjs` [10 modules] + size report). |
| **Tier 2 (`--invariants`)** | `./scripts/verify.sh --invariants [--strict]` | Checks `cargo tree --edges normal -e features` (`rayon`/`linfa`/`wgpu` absence across all 27 `egraph*` workspace crates, plus `getrandom`-free enforcement across the 25 pure-Rust crates and `egraph-wasm` default & `--no-default-features` [= 26 crates; `egraph-python` pulls legacy `getrandom`]), `std::thread`/`thread_rng` scans, `wasm32` compile across all 25 wasm32-capable `egraph*` crates (excluding host-only `egraph-python` and `egraph-cli`), and cross-target packaging metadata via `scripts/verify_helpers.py` (`<= ~500L` helper CLI covering `V6_CRATE_SUBDIRS`, `crates/python`, `crates/wasm`, `crates/python/pyproject.toml`, and `crates/wasm/package.json` `version` + npm provenance `repository`). (`--mode report` tolerates legacy `v6-alpha` bloat; `--mode strict` is required for modern `egraph*` crates.) |
| **Tier 2 (`--parity`)** | `./scripts/verify.sh --parity` | Runs `scripts/parity_harness.py` delegating to `scripts/parity/*.py` (30 modules covering deterministic fixtures, adversarial `NaN`/error checks, and optional Node.js WASM cross-checks). |
| **Tier 2 (`--docs`)** | `./scripts/verify.sh --docs` | Auto-provisions `crates/python/docs/requirements.txt` (`sphinx`, `sphinx-rtd-theme`, `matplotlib`) in `$REPO_ROOT/.venv` if missing, builds Sphinx HTML + `sphinx -b doctest` (into cleaned temp dirs), TypeDoc from `crates/wasm/typedoc.json`, and `npm --prefix js/examples run build`. |
| **Tier 3 (`--all`)** | `./scripts/verify.sh --all [--build-wasm] [--strict]` | Full integration sign-off / pre-PR gate (`--rust --python --wasm --invariants --parity`; combine with `--docs` and `node crates/wasm/tests/playwright_smoke.mjs` for full cross-target release gates without `--strict`, reserving `--strict` for legacy `petgraph-linalg-kernel` audits). |

## 3. Mandatory Steps Before Completion

Whenever a task is ready to be completed:
1. Run `cargo fmt --all` and verify clean formatting (`cargo fmt --all -- --check`).
2. Run `./scripts/verify.sh --fast` (or `--rust` / `--python` / `--wasm` / `--all` / `--docs` matching scope; note legacy `petgraph-linalg-kernel` clippy warnings require `--strict` to surface, `--rust` and `--python` default to release mode with `--debug-rust` / `--dev-py` available for debug opt-in, and `--fast` stays debug).
3. Verify `clippy.toml` (`std::thread` forbidden), `scripts/verify_helpers.py` (`<= ~500L` packaging/package-list helper), and `./scripts/check_invariants.sh` produce zero new violations; always pass `--edges normal` when inspecting dependencies manually with `cargo tree --edges normal -e features` so dev-dependencies do not trigger false positives, ensure `Cargo.lock` exists (`cargo generate-lockfile`), and never merge `cargo tree` stderr into stdout (`2>&1`) so lockfile-generation messages cannot trigger false positives. Run both the workspace-wide banned-dependency scan (`cargo tree --workspace --edges normal -e features | grep -E '(^|[^[:alnum:]_-])(rayon|linfa|linfa-nn|linfa-clustering|wgpu)([^[:alnum:]_-]|$)'` returning zero matches) and strict per-crate `getrandom` + feature-matrix checks across all 27 `egraph*` crates (45 total workspace crates including 18 legacy `petgraph-*` crates): `egraph-core`, `egraph-ffi`, `egraph-petgraph`, `egraph-dataset`, `egraph-spatial-{trees,fft,crossings}` + `egraph-spatial` umbrella, `egraph-linalg` + `egraph-linalg-{mds,amg}`, `egraph-neighborhood`, `egraph-clustering`, `egraph-metrics-{geometry,cluster}` + `egraph-metrics` umbrella, `egraph-layout-{constraints,stress,force,neighbor,sgd,multilevel}` + `egraph-layout` umbrella, `egraph` facade, `egraph-cli`, `egraph-python`, and `egraph-wasm` — covering `ALL_FEAT_CRATES` (12 crates `--all-features`), `NO_DEF_CRATES` (10 crates `--no-default-features`), `BASELINES_CRATES` (5 crates `--no-default-features --features baselines`), `DELAUNAY_CRATES` (5 crates `--features delaunay`), and `egraph-wasm` default `full = ["delaunay"]` & `--no-default-features`.
4. **PyO3 `extension-module` unit-test rule**: Pure-Rust helpers tested under `#[cfg(test)]` inside `crates/python` MUST return plain Rust types (`Result<_, String>` or `Option<_>`), never `PyErr` / `PyValueError`, so `cargo test --workspace` and `cargo nextest run --workspace` link cleanly on macOS without `libpython` symbols.
5. For Python binding changes, verify inside the worktree's isolated `.venv` (never pollute `/Users/likr/diffusion-kernel-experiments/.venv` from an unmerged worktree), and confirm `.venv/bin/mypy --strict` across `crates/python/python/egraph` and all 25 strictly typed domain test files (`TYPED_PY_TEST_NAMES` in `scripts/verify.sh`), `.venv/bin/mypy --strict --ignore-missing-imports scripts/verify_helpers.py scripts/parity_harness.py scripts/parity/` (as enforced in CI), and `.venv/bin/stubtest egraph` across all 25 package modules (`__init__.py`, `interop.py`, `_core.pyi`, `_core_types.{py,pyi}`, and the 21 `_core_<domain>.{py,pyi}` pairs, with `scipy`, `networkx`, and `igraph` installed for `egraph.interop`) pass cleanly.
6. **WASM `--no-default-features` flag placement & Domain-Named Test Registration**: `wasm-pack test --node` forwards trailing options directly to `cargo test`, so pass `--no-default-features` directly WITHOUT `--` (for example: `wasm-pack test --node crates/wasm --no-default-features --test <domain>`), which `verify.sh --wasm` runs automatically as `wasm_test_minimal` across all 26 feature-ungated domain `[[test]]` targets (`WASM_MINIMAL_TARGETS`), alongside default `wasm_test_all` and `wasm_test_legacy` (`--features legacy`), and `.github/workflows/ci.yml` / `.github/workflows/release.yml` run in `wasm-pipeline` / `build-wasm`. By contrast, `wasm-pack build` requires `-- --no-default-features` after `--`. Name all newly added Rust, Python, and WASM test files after their domain/feature (`tests/<domain>.rs`, `crates/python/tests/test_<domain>.py`, `crates/wasm/tests/<domain>.rs`)—never after workflow phases or milestones (`v6_m*`, `v6_w*`, `m4_lane*`). Keep `crates/wasm/Cargo.toml` `[[test]]` entries, `WASM_MINIMAL_TARGETS` in `scripts/verify.sh`, `.github/workflows/ci.yml`, and `.github/workflows/release.yml` synchronized whenever new feature-ungated WASM integration tests are added. After `--build-wasm` (`crates/wasm/scripts/assemble_pkg.mjs` + `crates/wasm/scripts/assemble/*.mjs` [11 modules], `crates/wasm/tests/node_esm_smoke.mjs` + `crates/wasm/tests/esm_smoke/*.mjs` [10 modules]) and `npm --prefix js/examples run build`, run `node crates/wasm/tests/playwright_smoke.mjs` to verify Chromium `memory.grow` detach recovery, `N=5,000` `runProgressive` `<= 10 ms`/frame budget, and all 13 `js/examples` routes.
7. **Single-thread SciPy / DKE micro-benchmarks**: Run comparative benchmarks from `egraph-rs/.venv` under explicit single-thread guards (`OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 NUMEXPR_NUM_THREADS=1`) with DKE kept strictly read-only (stub `sys.modules["utils"]` if needed to avoid `matplotlib` imports). Report pure-Python/SciPy-sparse graph preprocessing (`1+2hop`, `Track-A`) separately from C++ `_sparsetools`-backed SciPy SpMM kernels (`DoG-Var`).
8. **Local Release Packaging Clean-Env Smoke Recipes**:
   - **Python wheel & `sdist`**: Build into a scratch output dir under `<appDataDir>/scratch/teamwork_tmp/<id>` (`maturin build --manifest-path crates/python/Cargo.toml --release -o "$TMP/dist"` and `maturin sdist --manifest-path crates/python/Cargo.toml --out "$TMP/dist"`), then install each into a fresh `python3 -m venv` (without `egraph-rs` editable checkout on `sys.path`) and verify `import importlib.metadata as md, egraph as eg; assert eg.__version__ == md.version("egraph") == "<pep440>"` (matching `CARGO_PKG_VERSION` in PEP 440 form, e.g. `6.0.0a8`, and intentionally omitted from `egraph.__all__`) + `CsrGraph` / `TsNetSolver` / `SgdSolver.sparse_barrier_dog` / `evaluate_metrics` smoke execution. See `egraph-rs-release` for live PyPI/npm post-tag verification and canonical `evaluate_metrics` keys.
   - **npm ESM tarball**: Run `(cd crates/wasm && npm pack --dry-run && npm pack --pack-destination "$TMP")` after `--build-wasm`, verify `package/package.json` retains `"repository": {"type": "git", "url": "git+https://github.com/likr/egraph-rs.git", "directory": "crates/wasm"}` for `--provenance`, and smoke-import the unpacked tarball in Node.js ESM (`npm install --prefix "$TMP/consumer" "$TMP"/egraph-*.tgz`).
9. **Synthetic NP2 Test Fixtures for `SpatialIntruderRefiner`**: Because `SpatialRefinerConfig` defaults (`w_fn=0.0`) preserve initial 1-hop edge lengths, avoid asserting NP2 improvements on tiny lattices with an artificially stretched single-node edge whose outcome depends on RNG permutation order (e.g., after Lemire RNG refactoring). Use realistic folded fixtures (such as a `2x8` folded grid strip) where 1-hop edges remain near unit scale while distant `>2`-hop layers overlap, verifying across both `float64` and `float32`.
10. Always pass `--no-pager` on `git diff`, `git log`, and `git show` commands.
11. In swarm sessions, post a brief `@coordinator [interim]` status update on the board before starting any command expected to take `>60s` to prevent false monitor `[stall]` alerts.
12. **SHA-Keyed Verification Deduplication (No Redundant Full Re-Runs)**:
    - Never re-run `./scripts/verify.sh --all --build-wasm --docs` on an unchanged `HEAD` SHA + clean working tree if a previous gate already produced a passing `--json-summary` for that exact `HEAD` (e.g., after a zero-diff fast-forward merge). Verify `git rev-parse HEAD` and `git status --porcelain`, then run only delta-scoped checks or independent adversarial probes.
    - In multi-agent final acceptance gates on an unchanged `HEAD`, run `./scripts/verify.sh --all --build-wasm --docs --json-summary <path>` once in Phase 1; have Phase 2 reviewers/challengers inspect the SHA-stamped summary and focus on complementary checks (diff forensics, isolated consumer probes, `tsc`, Playwright), reserving at most one independent full re-run for a mandatory post-victory auditor.
    - For **version-bump-only commits** (zero Rust/Python/WASM logic diffs; only manifest/lockfile/docs bumps per `egraph-rs-release`), run `EGRAPH_PARALLEL_WORKERS=1 ./scripts/verify.sh --invariants --docs` plus clean-env wheel/`sdist`/`npm pack` smoke checks instead of repeating full Rust/Python/WASM unit suites already green on the parent commit.
    - Reserve `--strict` for explicit legacy-crate audits (`petgraph-linalg-kernel` carries baseline clippy warnings); standard integration and release gates use `--all --build-wasm --docs` without `--strict`.
13. **TypeScript Declaration Check after `--build-wasm`**:
    - Whenever `crates/wasm/scripts/assemble_pkg.mjs`, `crates/wasm/scripts/assemble/*.mjs` (11 modules), or WASM bindings change, always run `npx tsc --noEmit` against the assembled `crates/wasm/pkg/index.d.ts` before handoff to catch stripped or overwritten type exports early.
14. **Brute-Force Oracle & Adversarial Edge-Case Testing Before Review**:
    - For any change to `egraph-spatial*`, `egraph-linalg*`, `egraph-layout*`, or `egraph-metrics*` kernels, authors MUST cover before requesting review:
      - Randomized + degenerate brute-force $O(M^2)$ / $O(N^2)$ oracle tests for geometric kernels (collinear overlaps, shared endpoints, floating-point tie-breaks, periodic boundaries).
      - Graph & layout boundary cases: empty (`N=0`), singleton (`N=1`), edgeless, **directed graphs with reciprocal edges `(u, v)` + `(v, u)`** (catching inclusion-exclusion `saturating_sub` bugs), mixed connected + isolated degree-0 vertices, and **1D / axis-aligned / 2-cluster collinear layouts** (ensuring isotropic scale extraction uses `&&` not `||` on axis spans).
      - Iterative linear solver precision sensitivity: when solver outputs feed nonlinear transforms such as `-log(...)` (e.g., `RHGH`), validate end-to-end distance accuracy against exact dense solves (using tight tolerances like `rel_tol=1e-12`, not `1e-8`).
      - Cross-target Native vs. WASM parity fixtures: use asymmetric graphs (or rotation-invariant comparisons) for spectral/PivotMDS pipelines so multiplicity-2 eigenvalues do not trigger false 90-degree eigenbasis flips from `1e-16` FMA differences.
15. **Structured Sync Verification Over Static Shell Parsing**:
    - Verify synchronization across `Cargo.toml`, `scripts/verify.sh`, `scripts/verify_helpers.py`, `scripts/check_invariants.sh`, and `.github/workflows/{ci,release}.yml` via structured metadata parsing (`cargo metadata`, TOML/YAML/JSON, `verify_helpers.py`) and live `--json-summary` outputs rather than building custom static Bash interpreters inside audit scripts.
    - When adding or refactoring crate/test matrices in `scripts/verify.sh`, prefer exposing machine-readable lists from `scripts/verify_helpers.py` so cross-file sync checks stay trivial and deterministic, and never spend `> 2` iterations hardening temporary scratch verification scripts.
